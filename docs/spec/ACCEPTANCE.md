# Приёмка и доказательства

Документ связывает критерии оценивания с требованиями спецификации и с тем,
чем каждое из них подтверждается. Непроведённая проверка помечается
`NOT_RUN`; число, полученное измерением, — `RESULT`; число-цель — `TARGET`.
Подменять одно другим нельзя.

Актуальность: 23.09.2026, финальная сборка `faf8d3f` — после двух раундов жюри (T-50…T-62); прогон качества — QUALITY.md §13, нагрузочный — PERFORMANCE.md §12.

## 2. Критерии защиты

Четыре вопроса, по шкале 1–3 каждый.

| Вопрос | Что показываем | Чем закрываем |
|---|---|---|
| Доверие: решение действительно защищает | живой прогон текста жюри; блок «что фактически ушло в модель»; ловушки | демо-стенд, тест-перехватчик downstream |
| Внедряемость: можно поставить в реальные системы | цифры latency вместо обещаний; настройка под систему без правки кода; новый тип ПД без правки ядра | отчёт производительности, README, конфигурация с горячей перезагрузкой |
| Сила решения: чем лучше базового | токенизация и синтетика, комбинации типов, документы кроме паспорта, честный разбор, где подход даёт сбой | реестр решений, раздел ограничений |
| Команда: справятся ли дальше | объяснение архитектуры за 1–2 минуты, честные ограничения, понимание цены ошибки | `ARCHITECTURE.md`, раздел незакрытых пробелов в `DECISIONS.md` |

> Стоп-сигнал: утечка реальных персональных данных в модель на живом демо —
> провал ключевой функции, а не минус балл. Отсюда приоритет
> теста-перехватчика над всеми остальными проверками.

## 4. Методика измерений

**Качество.** Корпус порождается генератором, который намеренно не использует
грамматики и справочники детектора: иначе оценка проверяла бы совпадение кода
с самим собой. Считаются precision, recall и F1 по каждому типу, доля
избыточного маскирования, число сработавших ловушек, ошибки восстановления.
Отчёт фиксирует версию корпуса, seed и версию правил — без них прогоны
несравнимы.

Заявленный ТЗ уровень 95% подтверждается только собственной методикой:
формула официальной метрики не опубликована (пробел EXT-01), поэтому
совместимость с официальным расчётом не утверждается.

**Производительность.** Закрытый контур: фиксированное число соединений,
каждое ждёт ответа перед отправкой следующего запроса. Пропускная способность
равна `соединения / средняя латентность` — выше этого значения выдать
невозможно, ограничивает конкурентность клиента.

Измеряется только время сервиса; ожидание модели учитывается отдельной
метрикой. Фиксируются: goodput, среднее, p50, p95, p99, ошибки, `B/op` и
`allocs/op` ядра, RSS и куча, затраты на сборку мусора, запас до предела
памяти, условия измерения.

**Безопасность.** Проверка утечки ведётся поиском **каждого** размеченного
значения по отдельности в журнале, экспозиции метрик, телах ответов и в
фактически отправленном в модель теле. Сравнение целых строк не годится: оно
пропускает частичную утечку. Проверка кода ответа и содержимого журнала не
заменяет перехват исходящего трафика.

## 6. Что сознательно не доказывается

- Соответствие внутренним стандартам ИБ банка: стандарты не приложены
  (пробел EXT-03). Архитектура сама по себе соответствие не доказывает.
- Гарантии доступности downstream-модели: лимиты не документированы
  (пробел EXT-02). Одиночный успешный вызов SLA не подтверждает.
- Совместимость выбранного срока жизни соответствий с расписанием
  проверяющей системы: верхняя граница паузы между шагами не задана
  (пробел EXT-04).
- Производственная готовность: она не оценивается, и заявлять её незачем.
