# Реестр проектных решений ai-gateway

Документ фиксирует решения, принятые при проектировании, вместе с основанием
и ценой каждого. Решение здесь — нормативно: реализация не вправе выбрать
иначе, не изменив эту запись.

Дата фиксации: 22.09.2026. Источник большинства решений — интервью с
владельцем продукта (раздел 2). Внешние ограничения — раздел 1.

## 1. Факты, определившие проектирование

Ответы организаторов хакатона имеют приоритет над пересказами ТЗ. Ссылки вида
`A6.1` ведут в [docs/context/07-clarifications.md](../context/07-clarifications.md).

| ID | Факт | Что из него следует |
|---|---|---|
| F-01 | Эталонной маски не существует; метрика сравнивает качество сокрытия с оригиналом (`A3`, `A6.1`) | Формат маски выбираем сами. Задача — скрыть значение полностью, а не угадать образец |
| F-02 | Длина маски на оценку не влияет, замена возможна любыми символами (`A2.2`, `A4.3`) | Типизированный плейсхолдер допустим и предпочтителен |
| F-03 | Частичное раскрытие символов снижает оценку (`A4.1`) | Скрываем значение целиком, инициалы и хвосты номеров не оставляем |
| F-04 | Маскирование служебных слов штрафуется как избыточное (`A4.5`) | Границы спана держатся точно по значению |
| F-05 | Пропуски штрафуются сильнее лишних масок (`A1.1`) | При равенстве аргументов выбираем маскирование |
| F-06 | Закрытый контур, до 200 одновременных коннектов (`A2.3`) | Пропускная способность равна `200 / средняя латентность`. Цель 1000 RPS эквивалентна средней латентности 200 мс |
| F-07 | Измеряется только время нашего сервиса, без модели (`A6.3`) | Порог относится к добавленной обработке прокси |
| F-08 | На обратный шаг всегда приходит наша маска с тем же id (`A1.5`, `A6.5`) | Для автопроверки достаточно точного возврата сохранённой строки |
| F-09 | `payload_id` повторяется только при ошибке или 429 (`A6.5`) | Прямой шаг обязан быть идемпотентным |
| F-10 | Ограничение доступа не распространяется на контракт автопроверки (`A6.6`) | `/process` открыт; продуктовый контур требует ключ |
| F-11 | Автопроверка кода не отсекает решение, но влияет на баллы (`A4.8`, `A6.2`) | Чистота кода важна, но не является блокером |
| F-12 | Реальный вызов модели не обязателен, AlfaGen для демо разрешён (`A4.7`, `A6.7`) | Делаем реальный вызов: на защите это сильнее заглушки |
| F-13 | Пять невалидных ответов подряд останавливают весь прогон; 429 невалидным не считается | Отказ в обслуживании на `/process` дороже избыточного маскирования |

Два жёстких порога вне системы баллов: без доступного публичного URL с
`POST /process` решение не оценивается вовсе; без README с описанием настроек
критерий «Гибкая настройка» обнуляется.

## 2. Решения владельца продукта

Записано по итогам интервью. Формулировки отражают принятый выбор, а не
рекомендацию интервьюера.

| ID | Вопрос | Решение | Основание и цена |
|---|---|---|---|
| D-01 | Репозиторий | Автономная разработка в этом репозитории: свой модуль, спецификации, код и тесты. Соседний репозиторий — только референс | Скорость. Цена: результат придётся переносить в командный репозиторий отдельным шагом |
| D-02 | Развёртывание | Собственный VPS с публичным адресом. Поставка: `Dockerfile`, `docker-compose.yml`, инструкция | Надёжнее туннеля на пятиминутном прогоне. Цена: нужен доступ к серверу |
| D-03 | Механизм детекции | Только детерминированный: грамматики, ручные сканеры, справочники, контекстные признаки, контрольные суммы. Нейросетей внутри защиты нет | Бюджет 200 мс на пике исключает модель в контуре. Решение объяснимо жюри. Цена: полнота зависит от качества правил и справочников |
| D-04 | Формат маски | Типизированный плейсхолдер `[ФИО_1]`, `[КАРТА_1]` | Полное сокрытие даёт максимум по F-01–F-03; тип остаётся виден модели, смысл запроса сохраняется; разные значения не схлопываются в одинаковую маску. Фраза ТЗ §4.3 «с сохранением местоположения знаков» читается как побайтовое восстановление исходной строки (REQ-103), а не как равнодлинная маска: длина маски на оценку не влияет (`A4.3`); структуру значения при необходимости сохраняет стратегия `asterisks` |
| D-05 | Downstream-модель | Реальный вызов AlfaGen по контракту `docs/api-alfagen/`. Переключатель `llm.mode: alfagen \| stub` | Живая интеграция сильнее на защите; переключатель страхует демо от сетевых сбоев |
| D-06 | Дополнительные возможности | Берём все четыре: стратегии маски по потребителю, маскирование по комбинации типов, документы кроме паспорта РФ, нагрузочный отчёт с целью 2000 RPS | Критерий 7 даёт по баллу за уверенно показанное, максимум три. Цена: объём |
| D-07 | Хранилище соответствий | In-memory, шардированное, с TTL и лимитами, за интерфейсом `Store` | Один бинарник, нулевая внешняя зависимость в прогоне, субмиллисекундный доступ. Цена: при рестарте соответствия теряются |
| D-08 | Инструментарий проверки | Полный: генератор размеченного корпуса, проверка качества, нагрузочный прогон | Без собственных измерений нельзя утверждать ничего о качестве и латентности |
| D-09 | Демонстрация | Одностраничный стенд, встроенный в бинарник | Критерий 8 и защита 28.09 оценивают живой прогон текста жюри |
| D-10 | Поведение при отказе защиты | Разное по контурам. Продуктовый прокси: строгий fail-closed, HTTP 500, наружу не уходит ничего. `/process`: перехват отказа и маскирование строки целиком | F-13: серия отказов обрывает весь прогон. Избыточная маска — штраф по одному элементу, утечки нет |
| D-11 | Системы-потребители | Заводятся в `config.yaml`: ключ, допуск, типы ПД, стратегия маски, право демаскирования, комбинации. `/process` без ключа работает под изолированным потребителем `benchmark`; продуктовые эндпоинты требуют ключ | F-10 снимает требование защиты автопроверки, но требования ТЗ §3.2.4 и критерий 4 остаются |
| D-12 | Поведение при неоднозначности | Маскируем по умолчанию, но действуют явные контр-правила: ролевые слова, топонимы-производные, отделение банка, публичные контакты организаций | F-05 против критерия 3. Контр-правила лежат в справочнике, а не в коде |
| D-13 | Доска задач | Единый каталог `tasks/` со стабильными именами файлов, статус в YAML-шапке, сводка в `INDEX.md` | Пути не меняются, ссылки между задачами и из спецификации не ломаются |
| D-14 | Параллелизм | До трёх агентов волнами. Волна 0 последовательная и фиксирует контракты пакетов | Файловые конфликты исключаются владением: у каждой задачи свой набор файлов |

## 3. Решения, принятые при реализации

Приняты автором реализации в рамках решений раздела 2; каждое проверяемо
тестом.

| ID | Решение | Основание | Проверка |
|---|---|---|---|
| I-01 | Нормализованная копия текста побайтово выровнена с оригиналом | Нижний регистр и «ё» → «е» для кириллицы и латиницы не меняют длину в UTF-8. Сканеры сравниваются со справочниками без пересчёта смещений. Руны, у которых нижний регистр имеет другую длину, копируются без изменений | `TestNormIsByteAlignedWithText` |
| I-02 | Маскирование — чистая функция от текста и политики; нумерация плейсхолдеров по порядку первого появления значения | Идемпотентность прямого шага и безвредность параллельных повторов получаются бесплатно, без singleflight и блокировок | `TestProcessMaskIsPureFunction`, `TestProcessForwardRetryIsIdempotent` |
| I-03 | Одинаковые значения одного типа получают один номер плейсхолдера | Текст остаётся связным, модель может рассуждать о «[ФИО_1] и [ФИО_2]» как о разных людях | `TestProcessMaskIsPureFunction` |
| I-04 | Направление `/process` определяется сопоставлением payload с сохранённым состоянием | Счётчик вызовов ломается на первом же повторе, который система делает при ошибке и 429 | `TestProcessMaskThenUnmask`, `TestProcessIdentityMaskRoundTrip` |
| I-05 | Известный `payload_id` с неожиданным текстом маскируется, но сохранённую запись не перезаписывает | По записи ещё может прийти обратный шаг | `TestProcessUnknownPayloadDoesNotClobberRecord` |
| I-06 | Ключ хранилища включает идентификатор потребителя | Иначе второй потребитель с тем же `payload_id` разрушает чужое соответствие | `TestProcessForeignConsumerDoesNotClobberRecord`, `TestProcessIsolatesConsumers` |
| I-07 | Знание `payload_id` не даёт права на демаскирование: проверяется разрешение потребителя | Идентификатор корреляции не является авторизацией | `TestProcessDemaskDeniedReturnsMask` |
| I-08 | Уверенность кандидата — перечисление сработавших условий (`Certain`, `Strong`, `Weak`, `Denied`), а не вероятность | Произвольный score нельзя объяснить и нельзя воспроизвести. Каждый уровень достижим ровно набором правил | `internal/detect` |
| I-09 | Слабый кандидат повышается до сильного, если в том же предложении есть достоверное значение другого типа | Реквизиты одного предложения относятся к одной сущности. Этот же механизм закрывает требование ТЗ §6 о маскировании по комбинации типов | `internal/detect` |
| I-10 | Контр-правила выражаются запретом (`Deny`), а не удалением кандидата | Сканеры независимы и не знают друг о друге; решение принимает движок | `internal/detect` |
| I-11 | Сканеры регистрируются через `init` в собственных файлах | Общий список не редактируется: параллельные задачи не конфликтуют, новый тип ПД добавляется без правки ядра | `internal/detect/registry.go` |
| I-12 | Переполнение хранилища на `/process` отвечает 429 с `Retry-After`, а не 500 | 429 не считается невалидным ответом и не приближает остановку прогона (F-13) | `TestOverloadReturns429WithRetryAfter` |
| I-13 | Неизвестные поля в теле `/process` не считаются ошибкой | Контракт организаторов их не запрещает; отвечать ошибкой значило бы придумать ограничение за проверяющую систему | `TestProcessAcceptsUnknownFields` |
| I-14 | Метрики разложены по массивам фиксированного размера с перечислимыми метками | Неограниченная кардинальность исключена по построению, а не соглашением: `payload_id` и текст запроса в метки попасть не могут | `internal/obs/metrics.go` |
| I-15 | Токен для метрики TPS определён как 4 байта; рядом публикуются байты | Согласованного токенизатора модели нет. Счётчик слов не является числом токенов модели, и выдавать его за него нельзя | `internal/obs/metrics.go` |
| I-16 | Ключ downstream-модели читается из `.env`, в конфигурации указывается только имя переменной | Конфигурация попадает в репозиторий и в ZIP; секреты туда попасть не должны | `config.yaml`, `.gitignore` |
| I-17 | Поле `stream` в запросе к модели сериализуется всегда, без `omitempty` | Контракт помечает поле необязательным, но AlfaGen отвечает HTTP 400 на запрос без него. Установлено перебором полей 22.09.2026: без `system` — 200, без `temperature` — 200, без `max_tokens` — 200, **без `stream` — 400**. Со значением false `omitempty` выбрасывал поле и ломал каждый вызов | Реальный вызов через прокси |
| I-18 | Профили `strict` и `balanced` различаются подъёмом по кластеру (I-09), а не порогом допуска: порог у обоих — `Strong`, подъём слабого кандидата выполняется только под `balanced`. `paranoid` допускает всё и в подъёме не нуждается | Совпадает с описанием в README и `config.yaml` и не трогает контракт конфигурации. Альтернативы отвергнуты (T-25): `strict` = только `Certain` отсекал бы и сильных кандидатов с маркером типа рядом; отказ от `strict` отнимал бы у потребителя рычаг. Цена измерена (QUALITY.md §9.2): на корпусе `b398b99b…` `strict` скрывает 0,9369 значений против 0,9729 у `balanced` — ради меньшей избыточности, ловушек не срабатывает ни под одним. Профиль потребителя `benchmark` остаётся `balanced` | `TestDetectProfilesDifferByCluster` |
| I-19 | Номер карты, не прошедший проверку Луна, получает уверенность `Strong`, если рядом маркер карты («карта», «card», платёжная система) и нет маркера договора; без маркера остаётся `Weak` | Синтетические и опечатанные номера в обращениях Луна не проходят, а под `strict` или вне кластера `Weak` не маскируется: номер с подписью «карта» уходил в модель открытым. Пропуск дороже лишней маски (AGENTS.md §4). `Certain` по-прежнему только у прошедших Луна (T-05 AC-2). Прогон качества на корпусе `b398b99b…` не изменился: сокрытие 0,9761, precision 1,0000, ловушек 0 из 144 | `TestScanDigits`, T-45 |
| I-20 | Одиннадцать цифр с «7»/«8» и кодом мобильной сети «9xx» — телефон `Strong` без маркера; английские маркеры `passport`, `phone`, `mobile`, `tel`, `driver`, `licen…` приравнены к русским | «Мой номер 89161234567» и «passport 4509 123456» уходили открытыми (бизнес-жюри 23.09). Форма мобильного номера достаточно специфична: сумма и дата так не записываются; номер договора той же формы снимается маркером договора, городские номера без маркера остаются `Weak`. Замер (T-53): сокрытие 0,9761 → 0,9803, `phone` 427 из 427, precision 1,0000, ловушек 0 из 144 | `TestScanDigits`, T-53 |
| I-21 | Точка вплотную между цифрами («12.03.1985») и после заглавного однобуквенного инициала («И.И.») предложение не завершает (`lex.Doc.isBreak`) | Любая точка как граница рвала дату и подпись на части: правило публичной персоны не видело паспорт за датой, подъём по кластеру — дату за инициалами («Пушкин Александр Сергеевич, 12.03.1985 г.р., паспорт …» уходил открытым, бизнес-жюри 23.09, раунд 2). Точка перед переводом строки по-прежнему граница. Замер (T-58): сокрытие 0,9888 / 0,9896 — без изменений, ловушек 0 из 144 | `TestSentenceBreakSkipsInnerDots`, T-58 |
| I-22 | Новый текст с уже использованным `payload_id` заменяет соответствие, если он не похож на маску; вход с плейсхолдером, токеном или `[ЗАЩИЩЕНО]` соответствие не трогает | Прежде запись не менялась никогда, и повтор набора с теми же идентификаторами в пределах TTL ломал обратный шаг: сервис отдавал маску, а при совпадении масок двух текстов — исходник первого (техническое жюри 23.09, раунд 2; собственный `loadtest` дал 1066 расхождений из 1066 на втором прогоне подряд). Контракт не смешивает две пары одного `payload_id` (A6.5), поэтому последний прямой шаг — действующий; защита от подделок (T-19 AC-5) сохранена правилом «похож на маску» | `TestProcessNewTextSameIDStartsNewPair`, `TestInvariantProcessForgedPlaceholders`, T-62 |
| I-23 | Цифровые формы раунда 2 жюри: номер при «номер/№ + заявка/обращение/транзакция/операция/заказ/трек» не маскируется (как номер договора); 10-значный ИНН и 13-значный ОГРН при слове организации («банка», «организации», «работодателя ООО») не маскируются; телефон из 10 цифр без 7/8 — при маркере или коде в скобках; «2» в «CVV2/CVC2» — часть маркера; госномер `А123ВС 77` — `vehicle_reg`, разрядка `А 123 ВС 77` — нет | Номера заявок и реквизиты организаций — не ПД физлица, а лишняя маска на них ломает смысл запроса (ложные срабатывания жюри); связь «номер + заявка» требуется явно, чтобы «Паспорт, указанный в заявке: 4509 123456» остался паспортом. Разрядка госномера совпадает по форме с «с 100 на 150». Замер (T-59): сокрытие 0,9888 → 0,9890 после слияния с T-61, precision 1,0000, ловушек 0 из 144; 56 проб — 34 утечки и 15 лишних масок → 0 и 0 | `TestScanDigits`, `TestScanDocs`, T-59 |

## 4. Осознанно не сделано

| Что | Почему |
|---|---|
| Распознавание ПД на изображениях в Base64 через OCR | Организаторы назвали задачу амбициозной и рекомендовали сосредоточиться на тексте (`A5`) |
| Внешнее хранилище соответствий (Redis, БД) | Интерфейс `Store` выделен, реализация подключается без правки вызывающего кода. В прогоне внешняя зависимость только добавляет латентность и точку отказа |
| Список фамилий справочником | Русских фамилий сотни тысяч. Работает морфология суффиксов, заглавная буква и позиция в конструкции ФИО |
| Kubernetes и горизонтальное масштабирование | Производственная готовность не оценивается. Запуск N реплик сам по себе масштабирование не доказывает, а in-memory хранилище между репликами не разделяется |
| Шифрование хранилища соответствий и терминирование TLS | ТЗ §3 называет шифрование среди средств защиты. Соответствия «маска → оригинал» живут только в памяти одного процесса с TTL (30 минут по умолчанию), на диск, в журнал, в метрики и в сеть не попадают; доступ к памяти процесса модель угроз (`ARCHITECTURE.md` §4) относит к доверенной зоне. Шифрование в памяти ключом из того же процесса от этой угрозы не защищает, а TLS на публичном адресе — задача обратного прокси перед сервисом. Цена: при выносе хранилища наружу (Redis) шифрование поля оригинала становится обязательным — интерфейс `Store` это допускает без правки вызывающего кода |
| Допуск потребителя `benchmark` на `/process` | `/process` берёт потребителя по умолчанию без проверки `enabled`: отказ в обслуживании на контракте проверки обрывает весь прогон (F-13), а ограничение доступа на этот контракт не распространяется (F-10). Цена: закрыть приём `/process` настройкой нельзя, только остановкой сервиса |
