## 7.1. Метрика и правила маскирования

### Эталонной маски не существует

`A3`, `A6.1`. Правил маскирования по типам ПД нет, эталонной маски нет. Метрика
кастомизирована за счёт span-based логики и сравнивает **качество сокрытия
относительно оригинала**, а не близость к образцовой маске.

Пример `Иванов Иван Иванович → И. И. И.`, `4509 123456 → 45** ****56` из OpenAPI
в приложении A — иллюстрация формата обмена, а не спецификация преобразования.
Опираться на него как на обязательную конвенцию нельзя.

### Способ и длина замены — свободные

`A2.2`: разницы между `{INN_1}` и звёздочками нет, проверяется сам факт сокрытия
информации. `A6.1`: заменять можно на любые символы и/или группы символов.
`A4.3`: длина маски на оценку не влияет — `[ФИО]` вместо `Иванов Иван Иванович`
допустимо.

### Полнота сокрытия

`A4.1`: если оставить часть символов открытыми (`45 56`, `2200   9019`,
`i*@mail.ru`, инициалы `И. И. И.`), оценка **незначительно, но ниже**. Полное
сокрытие значения предпочтительнее частичного.

`A4.2`: разделители внутри значения — точки, дефисы, пробелы — оставлять или
скрывать на усмотрение команды.

### Избыточное маскирование штрафуется

`A3`: есть отдельная проверка на полное маскирование строки со штрафом, если это
избыточно.

`A4.5`: маскирование служебных слов («серия», «ул.», «года») вместе со значением
штрафуется как избыточное.

`A4.4`: если весь payload состоит только из значения, полное маскирование строки
избыточным **не** считается.

`A1.1`: лишние маски штрафуются **слабее**, чем пропуски.

Итоговый ориентир: скрывать значение целиком, границы спана держать точно по
значению, служебные слова и окружающий текст не трогать.

## 7.2. Нагрузка и производительность

### Профиль нагрузки

`A1.3`: нагрузка подаётся **с разгоном**, средний RPS около **330**, пики до
**1000**. Ответ `429` ошибкой не считается, но сохраняется для статистики.

`A2.3`: асинхронное обращение с параллельностью **до 200 одновременных коннектов**;
каждый коннект работает синхронно — ждёт ответа перед отправкой следующего запроса.
Это закрытый контур, имитирующий реальную нагрузку.

`A6.4`: 1000 RPS — это количество **любых** запросов к сервису, без разделения по
типам операций. Размеры текстов различные.

Прямое следствие закрытого контура: пропускная способность = 200 / средняя
латентность. Требование «держать 1000 RPS» эквивалентно «отвечать в среднем за
200 мс при 200 параллельных запросах».

| Целевой RPS | Требуемая средняя латентность |
|---|---|
| 330 (средний уровень прогона) | ≤ 600 мс |
| 1000 (пик) | ≤ 200 мс |
| 2000 (бонус из ТЗ §6) | ≤ 100 мс |

Выше значения `200 / латентность` выдать невозможно: пропускную способность
ограничивает конкурентность проверяющего клиента, а не ёмкость сервиса.

### Граница измерения

`A6.3`: измеряется **только ответ нашего сервиса**, время LLM в измерение не входит.
Используются среднее, p50, p95, p99.

Ориентир по latency берётся из ТЗ (**≤ 1 секунды**). Значение ≤ 0,5 секунды из
критериев оценивания организаторы назвали артефактом. Ранее зафиксированное
расхождение источников снято.

### Ресурсы сервера участника

Вопрос об ограничениях на ресурсы сервера участника задавался (`Q6.4`), ответа не
поступило. Ограничения считаем неустановленными.

## 7.3. Демаскирование, `payload_id` и ретраи

`A1.5`, `A6.5`: на обратный шаг **всегда** приходит наша собственная маска без
изменений, с тем же `payload_id`.

`A1.4`: количество демаскирований совпадает с количеством маскирований.

`A6.5`: `payload_id` отправляется повторно только при ошибке или `429`; в остальных
случаях он уникален для пары «маскирование → демаскирование». Срок хранения
соответствий — на усмотрение команды.

Следствия. Для прохождения автопроверки достаточно точного возврата сохранённой
исходной строки по `payload_id`. Восстановление плейсхолдеров в изменённом моделью
тексте — задача продуктового режима и демо, а не контракта проверки. Идемпотентность
по ретраям остаётся обязательной: повтор прямого шага должен вернуть ту же маску.

## 7.4. Авторизация и системы-потребители

`A4.6`: проверяющая система всегда шлёт запросы без заголовков — это одна и та же
«система по умолчанию».

`A6.6`: требование ограничения доступа **не распространяется** на контракт
автопроверки; баллы за отсутствие защиты этого эндпоинта сниматься не будут.

Следствие: список систем-потребителей и их настройки нужны ради требований ТЗ §3.2.4
и критерия «гибкая настройка и расширяемость», но не должны становиться обязательным
условием обработки запроса на `/process`.

## 7.5. Автопроверка кода

`A4.8`: проверка будет считаться успешной **в любом случае**, детального отчёта не
предусмотрено.

`A1.6`: около 6000 правил — code complexity, нарушения DRY/KISS, использование
deprecated-классов и зависимостей, «грязный код».

`A6.2`: автопроверка дополняет оценку жюри и напрямую в баллы не превращается, но по
её результатам баллы по связанным критериям могут быть **снижены** — например, по
критерию «Качество идентификации и маскирования ПДн» при низком качестве маскирования.

`A1.2`: прогон автоматизирован при отправке решения либо запускается вручную; доступа
к системе проверки у команд нет; последние версии сервисов гарантированно будут
оценены до начала судейства.

> Уточнение к [04-api-contract.md §4.1.1](04-api-contract.md): формулировка
> «решение, не прошедшее автоматическую проверку качества кода, не будет учтено»
> взята из ТЗ. По ответу `A4.8` эта проверка не является отсекающим барьером,
> но её результаты влияют на баллы через `A6.2`.

## 7.6. Демо и вызов LLM

`A6.7`: реальный вызов LLM не обязателен, допускается демонстрационный ответ.
Организаторов интересует прежде всего механизм маскирования и демаскирования,
а не само проксирование.

`A4.7`: использовать AlfaGen как внешнюю LLM в демо-прокси можно. Ограничения есть,
но только как защита от DDoS; при обычной работе в них не упереться.

## 7.7. Датасет и дополнительные сценарии

`A2.1`: 17 различных категорий; в них входят как отдельные слова, так и фразы и
предложения.

`A5`: обработка картинок, переданных в Base64, через OCR — на усмотрение команды.
Задача названа амбициозной, рекомендовано сосредоточиться на текстовом маскировании.

## 7.8. Организационное

`A2.4`: на вопрос о применении другого ИИ для планирования и ревью при написании кода
через AlfaGen получен ответ «нежелательно». Прямого запрета не сформулировано.

## 7.9. Что изменилось относительно прежнего прочтения контекста

| Прежнее прочтение | Факт по ответам организаторов |
|---|---|
| Результат сравнивается с эталонной маской | Эталона нет; сравнение качества сокрытия относительно оригинала (`A3`, `A6.1`) |
| Формат маски нужно угадать по примеру из OpenAPI | Формат свободный, длина не важна (`A2.2`, `A4.3`) |
| Нагрузка — открытый контур на 1000 RPS | Закрытый контур, до 200 коннектов, разгон, средний ~330 (`A1.3`, `A2.3`) |
| Расхождение latency 1 с против 0,5 с не разрешено | Ориентир — ТЗ, ≤ 1 с; 0,5 с названо артефактом (`A6.3`) |
| Latency может включать время LLM | Измеряется только ответ нашего сервиса (`A6.3`) |
| На демаскирование может прийти изменённый текст | Всегда наша маска без изменений (`A1.5`, `A6.5`) |
| Непрохождение автопроверки кода отсекает решение | Проверка успешна в любом случае (`A4.8`) |
| `/process` нужно защищать авторизацией | Не требуется, баллы не снимаются (`A6.6`) |

## 7.10. Открытые вопросы
