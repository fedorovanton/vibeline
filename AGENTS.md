# AGENTS.md — операционная инструкция для агентов

Проект: **`ai-gateway`** — сервис-прокси в цепочке «система-потребитель → LLM»,
который идентифицирует, маскирует и демаскирует персональные данные 17 категорий.
Трек «Модуль безопасности персональных данных» хакатона AlfaGen (Альфа-Банк).

Этот файл — нормативный. Решения ниже приняты и не пересматриваются агентом в
одиночку: расхождение с ними — повод остановиться и вернуть вопрос оркестратору,
а не повод изменить архитектуру по ходу задачи.

## 1. Границы работы

| Что | Значение |

| Рабочий репозиторий | этот репозиторий — автономный, здесь ведётся вся работа; пути в документах — от его корня |
| Соседний репозиторий | репозиторий-референс — **только чтение**; писать туда запрещено |
| Дедлайн загрузки zip | 23.09.2026, 23:59 МСК |

| Контракт LLM | `docs/api-alfagen/alfagen-api-contract.md` |

Worktree-процесс в этом репозитории **не требуется**: работаем в основном рабочем
каталоге. MCP-инструменты **не запрещены**. Правила соседнего репозитория-референса
о worktree и запрете MCP на нас не распространяются.

## 2. Два жёстких порога

1. **Доступный публичный URL с `POST /process` на момент прогона** — единственный
   отсекающий барьер. Без него решение не оценивается вообще, независимо от качества
   кода. Всё, что мешает выкатке и доступности, имеет наивысший приоритет.
2. **README с описанием настроек.** Без него критерий «Гибкая настройка и
   расширяемость» (0–4 балла) выставляется в **0** без компенсации.

Дополнительно: утечка немаскированных ПД на демо — не «минус балл», а провал
ключевой функции. Пропуск ПД штрафуется сильнее лишней маски.

## 3. Зафиксированные технические решения

| Решение | Формулировка |
|---|---|
| Язык | **Go 1.26**, один бинарник, модуль `ai-gateway` |
| Зависимости | Только по конкретному обоснованию; по умолчанию — стандартная библиотека |
| Детекция ПД | **Только детерминированная**: грамматики, ручные сканеры, словари, контекстные признаки, контрольные суммы |
| Запрещено внутри защиты | Нейросети, NER-модели, ONNX, эмбеддинги, LLM-арбитры. LLM — только downstream-получатель уже защищённого текста |
| Формат маски по умолчанию | Типизированный плейсхолдер: `[ФИО_1]`, `[CARD_1]`, `[PASSPORT_1]` |
| Полнота сокрытия | Значение скрывается **целиком**; частичное сокрытие (`45** ****56`, инициалы) оценивается ниже |
| Границы спана | Служебные слова («серия», «номер», «ул.», «года») в спан **не включаются** — это штрафуется как избыточность |
| Маскирование | Чистая детерминированная функция от `(payload, policy)` |
| Нумерация плейсхолдеров | По порядку первого появления спана в тексте |
| Идемпотентность | Следствие чистой функции: повтор прямого шага даёт ту же маску; гонки безвредны |
| Хранилище соответствий | In-memory, шардированное, с TTL, за интерфейсом `Store` |
| Демаскирование | Возврат сохранённой исходной строки по `payload_id` (для автопроверки) + восстановление плейсхолдеров в изменённом тексте (продуктовый режим) |

### Поведение при отказе защитной обработки — разное по контурам

| Контур | Поведение при панике/ошибке детекции |
|---|---|
| LLM-прокси (`/v1/*`) | **Строгий fail-closed**: HTTP 500, наружу не уходит ничего |
| `/process` | `recover` + маскирование строки целиком с сохранением оригинала в `Store` |

Обоснование второго: 5 невалидных ответов подряд останавливают нагрузочный прогон.
Маска на всю строку — потеря баллов по одному элементу; оборванный прогон — потеря
всего. Оба пути обязаны сохранить соответствие, иначе обратный шаг не пройдёт.

## 4. Потребители и конфигурация

Потребители заводятся в `config.yaml`. Поля на потребителя: ключ, `enabled`, список
типов ПД, стратегия маски, право демаскирования, правила комбинаций типов.

- `/process` работает **без ключа** под изолированным потребителем `benchmark` —
  проверяющая система шлёт запросы без заголовков, и требование ограничения доступа
  на этот контракт не распространяется.
- Продуктовые эндпоинты `/v1/*` **требуют ключ** — на них демонстрируется allowlist,
  отключение потребителя и право демаскирования.
- Изменение конфигурации не требует пересборки: SIGHUP-reload + валидация +
  публикация нового `Snapshot` через `atomic.Pointer`.

### Контр-правила ловушек

При неоднозначности — маскируем (пропуск дороже лишней маски), но действуют явные
контр-правила, которые снимают срабатывание:

- ролевые слова рядом с именем: «поэт», «писатель», «композитор», «художник»;
- топонимы-производные: «ул. Пушкина», «площадь Гагарина», «проспект Ленина»;
- адреса и контакты организаций: «отделение банка», «офис», публичные телефоны и
  email организаций.

Контр-правила живут в `internal/detect` вместе со сканерами и покрываются тестами
на ложные срабатывания наравне с тестами на пропуски.

## 5. Структура пакетов

| Путь | Ответственность |
|---|---|
| `cmd/ai-gateway/` | Запуск, чтение конфига, HTTP-сервер, graceful shutdown, SIGHUP-reload |
| `internal/config/` | Схема `config.yaml`, валидация, `atomic.Pointer[Snapshot]` |
| `internal/pii/` | Реестр типов ПД: идентификаторы, имена, метаданные |
| `internal/lex/` | Однопроходный лексер: токены, byte-offset, нормализация |
| `internal/detect/` | Движок, сканеры по типам, контекстные признаки, разрешение перекрытий, `dict/` через `//go:embed` |
| `internal/policy/` | Применение политики потребителя к найденным спанам |
| `internal/mask/` | Стратегии `placeholder \| asterisks \| token \| synthetic` |
| `internal/store/` | Интерфейс `Store` + шардированная in-memory реализация с TTL |
| `internal/llm/` | Клиент AlfaGen, таймауты, ретраи, stub-режим |
| `internal/obs/` | `slog` без ПД, метрики Prometheus (Latency / RPS / TPS) |
| `internal/httpapi/` | Роутинг, middleware, `/process`, `/v1/*`, `/healthz`, `/metrics` |
| `web/` | Демо-стенд, встроенный через `//go:embed` |
| `tools/corpusgen\|qualitycheck\|loadtest` | Генерация синтетического корпуса, замер качества, нагрузочный прогон |
| `docs/spec/` | `DECISIONS.md`, `SPEC.md`, `ARCHITECTURE.md`, `ACCEPTANCE.md` |
| `tasks/` | Доска задач |

Пакет не расширяет свою зону ответственности «по дороге»: новый тип ПД добавляется
в `internal/pii` + сканер в `internal/detect` + словарь в `detect/dict/`, без правок
`httpapi` и `mask`.

## 6. Доска задач `tasks/`

Файлы `tasks/T-NN-slug.md` со **стабильными именами**: путь задачи не меняется после
создания (на него ссылаются `depends_on` других задач и `INDEX.md`).

YAML-шапка задачи:

```yaml
id: T-07
title: Шардированное in-memory хранилище соответствий
owner: <агент или пусто>
status: backlog        # backlog | in-progress | review | done | blocked
wave: 2
depends_on: [T-03]
owns:
  - internal/store/store.go
  - internal/store/shard.go
  - internal/store/store_test.go
estimate: 90m
```

`tasks/INDEX.md` — сводная канбан-доска по всем задачам.

### Протокол агента

1. Прочитать файл задачи и `docs/spec/SPEC.md`.
2. Проставить `status: in-progress` и `owner`.
3. Менять **только** файлы из `owns`. Ни один файл вне `owns` не редактируется.
4. Прогнать команду проверки, указанную в задаче; прочитать её вывод и код возврата.
5. Проставить `status: review` и заполнить раздел «Журнал»: что сделано, что прошло
   проверку, что осталось непроверенным.
6. Оркестратор проверяет интеграцию, ставит `done` и обновляет `tasks/INDEX.md`.

Понадобился чужой файл — **не трогать**. Записать блокер в «Журнал», поставить
`status: blocked` и вернуть задачу оркестратору. Параллельно работают **до 3 агентов**,
волнами; задачи одной волны не пересекаются по `owns`.

## 7. Инварианты приватности

Самый важный раздел. Нарушение любого пункта — блокирующий дефект.

- **Никогда не логировать** сырые `payload`, значения ПД, обратимые соответствия,
  CVV, ПИН-коды, API-ключи — ни в логах, ни в трассах, ни в метриках, ни в текстах
  ошибок, ни в сообщениях паник.
- **Логируем**: этапы обработки, имена типов ПД, счётчики найденного, длительности,
  `request_id`, `payload_id`, `consumer`.
- **Labels метрик** — ограниченной кардинальности (тип ПД, потребитель, код ответа,
  маршрут). `payload_id`, `request_id` и любой текст запроса в labels не попадают.
- **Единственная точка выпуска в LLM.** Исходящий запрос формируется в одном месте
  `internal/llm`, и его предусловия перечислены явно: аутентификация пройдена,
  детекция завершена без ошибок, политика применена, все спаны заменены, запись в
  `Store` подтверждена. Любой отказ на любом шаге → **ноль исходящих запросов**.
- **Запись соответствия завершается до** успешного ответа на маскирование. Не
  наоборот: иначе обратный шаг получит маску, которой нет в хранилище.
- **Демаскируем только плейсхолдеры, выданные в рамках авторизованной области.**
  Знание `payload_id` авторизацией не является. Чужие, подделанные и неизвестные
  плейсхолдеры не раскрывают ничего и не приводят к утечке через сообщение об ошибке.
- **В тестах и бенчмарках — только синтетические данные.** Реальные ПД в репозиторий
  не попадают ни в каком виде, включая фикстуры и примеры в документации.
- **`.env` с ключом AlfaGen в git не коммитится.** Ключ передаётся заголовком
  `Authorization: <ключ>` **без** префикса `Bearer` (с `Bearer` API отвечает 400).

## 8. Go-практики

- **В hot path не использовать `regexp`.** Детекция — ручные сканеры по токенам
  лексера. Скомпилированные словари и правила — неизменяемый snapshot, общий для всех
  запросов и собранный один раз при старте/reload.
- **Byte-offset и rune-index не смешивать.** Спаны хранятся в byte-offset. Нормализация
  для поиска (регистр, `ё`/`е`, разделители) не должна менять незамаскированные участки
  результата. Аккуратно с UTF-8, кириллицей, составными символами, JSON-escapes и CRLF.
- **Контекст.** Пробрасывать `context.Context` через блокирующую работу, ставить
  дедлайны на внешние вызовы, прекращать работу по отмене. У каждой горутины есть
  владелец и условие выхода.
- **Границы.** Ограничивать размер входа, число кандидатов, число замен и ёмкость
  `Store`. При перегрузке — backpressure и предсказуемый ответ **429 с `Retry-After`**
  (проверяющая система его учитывает и ретраит; устойчивые 5XX останавливают прогон).
- **Буферы.** Ссылки на возвращаемые в пул буферы в долгоживущее состояние не
  сохранять — результат маскирования копируется до возврата буфера.
- **Ошибки.** Проверять и оборачивать безопасным контекстом (без ПД). Ресурсы закрывать
  на всех путях. Ретраить только идемпотентные операции с бюджетом и backoff.
- **Конфигурация.** Валидированный snapshot публикуется атомарно; обработчик запроса
  читает его один раз за запрос и работает с одной и той же версией до конца.

## 9. Проверка

| Команда | Когда |
|---|---|
| `gofmt -l <изменённые файлы>` | Всегда перед сдачей задачи |
| `go vet ./...` | Всегда |
| `go test ./...` | Всегда |
| `go test -race ./internal/store/... ./internal/httpapi/...` | При правках store, httpapi, конкурентного кода |

Проверка считается выполненной **только после того, как прочитан её вывод и код
возврата**. Непрогнанную проверку никогда не выдавать за успешную. Формулировки
«должно работать», «скорее всего проходит» в «Журнале» задачи недопустимы.

Числа в документации и отчётах помечаются: **TARGET** — цель без измерения,
**RESULT** — измеренное значение с указанием условий (конкурентность, размер входа,
длительность, перцентили).

### Обязательная проверка перехвата downstream

Единственное доказательство, что ПД не утекают в LLM:

1. Поднять **fake-LLM сервер**, который принимает запрос и сохраняет **фактическое
   тело** запроса.
2. Прогнать через прокси размеченные синтетические данные (корпус из `tools/corpusgen`).
3. Проверить, что в сохранённом теле **нет ни одного исходного значения ПД** из
   разметки — поиск по каждому размеченному значению, а не по выборке.
4. Отдельным сценарием смоделировать отказ защитной обработки и убедиться, что
   fake-LLM получил **ноль запросов**.

Чтение логов, кода ответа HTTP и визуальный осмотр вывода эту проверку **не заменяют**.

## 10. Сдача

ZIP на загрузку содержит **только исходники**. Не включаются: `.git`, собранные
бинарники, каталоги зависимостей и сборки, крупные датасеты, `.env` и любые секреты.
Архив — один, в формате `.zip`, с понятной структурой в корне.

Перед упаковкой убедиться, что: сервис поднимается по инструкции из README, `/process`
доступен по публичному URL, README описывает настройки потребителей и типов ПД,
в репозитории нет реальных ПД и ключей.
