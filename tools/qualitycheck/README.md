# qualitycheck — измерение качества маскирования

Инструмент шлёт каждую запись корпуса из [`tools/corpusgen`](../corpusgen/README.md)
на `POST /process`, затем возвращает полученную маску с тем же `payload_id` и
считает метрики качества.

## Почему отдельный модуль

У инструмента собственный `go.mod`, он не импортирует `ai-gateway` и не зависит
ни от чего, кроме стандартной библиотеки; это сторожится тестами
`TestNoGatewayImports` и `TestModuleIsStandaloneWithoutDependencies`. Сервис виден
только через HTTP-контракт: измерение, заглядывающее во внутренности детектора,
проверяет совпадение кода с самим собой, а не качество
(`docs/spec/ACCEPTANCE.md` §4).

## Запуск

```bash
cd tools/corpusgen && go run . -out /tmp/corpus.jsonl
go build -o /tmp/aigw ./cmd/ai-gateway && /tmp/aigw -config config.yaml &

cd tools/qualitycheck
go run . -url http://localhost:8080 -corpus /tmp/corpus.jsonl
go run . -corpus /tmp/corpus.jsonl -json report.json   # таблица и машинный отчёт
go run . -corpus /tmp/corpus.jsonl -json -             # только JSON в stdout
```

| Флаг | Значение |
|---|---|
| `-url` | адрес сервиса с контрактом `POST /process` |
| `-corpus` | файл корпуса в формате JSON Lines |
| `-json` | файл машинного отчёта; `-` — стандартный вывод вместо таблицы |
| `-verbose` | печатать значения ПД (см. ниже) |
| `-timeout` | предел на один запрос, по умолчанию 10 с — как в официальной проверке |
| `-concurrency` | число одновременно проверяемых записей (по умолчанию 16) |
| `-seed`, `-count`, `-long` | параметры генерации корпуса; попадают в отчёт |
| `-limit` | прогнать только первые N записей |

## Приватность отчёта

По умолчанию в отчёте нет **ни одного** значения персональных данных: только
типы, идентификаторы записей и позиции. Значения печатаются лишь при явном
`-verbose` — и в таблицу, и в JSON. Инвариант проверяется тестами
`TestRenderHasNoValuesWithoutVerbose`, `TestWriteJSONHasNoValuesAfterRedact` и
`TestReportFromRunHasNoValues`.

## Метрики

**Сокрытие — главная метрика.** Для каждого размеченного значения проверяется,
что его нет в ответе. Проверка ведётся по каждому значению отдельно: сравнение
целых строк пропускает частичную утечку. От границ спана и от стратегии замены
метрика не зависит — эталонной маски не существует
(`07-clarifications.md` §7.1).

`precision`, `recall`, `F1` считаются по факту сокрытия, а не по совпадению
границ: TP — размеченное значение исчезло из ответа, FN — осталось,
FP — ловушка этого типа исчезла из ответа. У типов, для которых корпус не
содержит ловушек, источника FP нет, и precision равна единице по построению;
отчёт показывает число ловушек рядом, чтобы это было видно.

**Спорные утечки.** Если значение встречается в тексте и вне разметки — короткое
число или обиходное слово попадается в длинном тексте случайно, — подсчёт
вхождений не отличает уцелевший спан от обычного текста. Такие спаны засчитываются как утечки, помечаются в отчёте, и рядом
печатается `recall↑` — верхняя граница, если считать их скрытыми.

**Избыточность — вспомогательная метрика**, и от границ она зависит напрямую:
доля байтов оригинала, не сохранившихся в ответе, вне размеченных спанов.
Соглашение корпуса о границах может не совпадать с разметкой детектора, поэтому
высокая избыточность означает в первую очередь расхождение конвенций.
Выравнивание оригинала и маски приблизительное — точного соответствия между
произвольной маской и оригиналом не существует; спорные байты трактуются как
замаскированные.

**Восстановление.** Ответ на обратный шаг сравнивается с оригиналом побайтово,
включая пунктуацию и пробелы.

Отчёт фиксирует отпечаток корпуса, seed, параметры генерации и версию сервиса:
без них прогоны несравнимы между собой.
