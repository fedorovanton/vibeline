## Цель

Замкнуть цепочку «система-потребитель → модуль → LLM → потребитель»:
запрос маскируется, уходит в AlfaGen, ответ демаскируется и возвращается
потребителю. Это то, что жюри смотрит на живом демо, и то, где утечка
означает провал ключевой функции, а не минус балл.

## Подтверждённый контракт AlfaGen

Проверен живым запросом 22.09.2026 — API отвечает.

- `POST https://alfagen.alfabank.ru/continue-dev/v1/chat/completions`
- Заголовок `Authorization: <ключ>` — **без префикса `Bearer`**. С `Bearer`
  сервер отвечает 400.
- Модель `deepseek-ai/DeepSeek-V4-Flash-0731`.
- Тело и ответ — OpenAI-совместимые.
- Полная схема: `docs/api-alfagen/alfagen-api-contract.md`.

Ключ читается из переменной `ALFAGEN_API_KEY`, которая подгружается из `.env`
при старте. В коде, конфигурации и логах ключа быть не должно.

## Что сделать

### `internal/llm/client.go`

Клиент OpenAI-совместимого чата. Переиспользуемый `http.Client` с настроенным
транспортом: пул соединений, keep-alive, дедлайн из конфигурации.
Контекст пробрасывается, отмена прекращает работу.

Повторы — только для сетевых ошибок и кодов 429, 502, 503, 504, с бюджетом
попыток, экспоненциальной задержкой и соблюдением дедлайна запроса. Коды 400,
401, 403 не повторяются: повтор их не исправит.

Сообщения об ошибках не содержат ни тела запроса, ни ключа.

### `internal/llm/stub.go`

Режим `llm.mode: stub` — детерминированный ответ без сети. Нужен, чтобы демо
не зависело от доступности сети, и чтобы тесты не ходили наружу.
Ответ должен показывать, что модель «увидела» именно маску: пусть он цитирует
полученные плейсхолдеры.

### `internal/gateway/proxy.go` — инвариант fail-closed

Единственная точка выпуска данных наружу. Её предусловия перечисляются явно
в коде и обязаны быть выполнены **все**:

1. Потребитель аутентифицирован и допущен.
2. Детекция завершена без ошибки.
3. Политика применена.
4. Все отобранные спаны заменены.
5. Соответствие сохранено в хранилище.

Нарушение любого — запрос в модель **не отправляется**, клиент получает
HTTP 500 без персональных данных в теле. Ни исходный, ни частично
обработанный текст наружу не уходит. Это отличается от поведения `/process`,
где применяется безопасный откат: там отказ обрывает весь нагрузочный прогон,
здесь — нет.

Демаскирование ответа модели: восстанавливаются только те плейсхолдеры,
которые были выданы в этом же запросе и разрешены политикой потребителя.
Неизвестный или подделанный плейсхолдер в ответе модели не раскрывает ничего.
Если у потребителя `demask: false` — ответ возвращается как есть.

Ответ модели дополнительно **сканируется заново**: модель могла сама
сгенерировать персональные данные, которых не было в запросе.

### `internal/httpapi/proxy.go`

`POST /v1/chat/completions`, OpenAI-совместимый. Аутентификация по ключу:
заголовок `Authorization: Bearer <ключ>` или `X-API-Key: <ключ>`. Ключ
сопоставляется с потребителем через `snap.Consumers.ByKey`. Неизвестный или
отключённый потребитель — 401 без подробностей о том, какая именно проверка
не прошла.

Маскируются поля `content` всех сообщений. Ответ возвращается в том же
формате, что вернула модель, с демаскированным `content`.

Метрики: `obs.EndpointChat`, `obs.OpProxy`, а также `Metrics.LLM` для времени
самой модели — оно **не входит** в измеряемое время сервиса.

### Обязательный тест перехвата downstream

Самая важная проверка задачи. Поднимается фальшивый сервер модели
(`httptest.Server`), клиент направляется на него.

1. В запрос кладётся текст с размеченными синтетическими значениями.
2. Перехватывается **фактически отправленное тело**.
3. По каждому размеченному значению выполняется поиск в этом теле — ни одно
   не должно найтись. Сравнение целого payload не годится: оно пропустит
   частичную утечку.
4. Отдельный случай: защита завершается отказом — фальшивый сервер обязан
   получить **ноль** запросов.

Проверка кода ответа и содержимого логов эту проверку не заменяет.

### Блокер: одна строка в `internal/httpapi/server.go`

Файл вне `owns` и не редактировался. Маршруты продуктового контура объявлены
методом `(*Server).registerProxyRoutes(mux *http.ServeMux)` в
`internal/httpapi/proxy.go`. Чтобы контур заработал, оркестратору нужно
добавить в `NewServer` **ровно одну строку** — после `mux := http.NewServeMux()`
и до создания `s.http` (естественное место — сразу за регистрацией `/process`):

```go
	s.registerProxyRoutes(mux)
```

Строка проверена на копии репозитория в отдельном каталоге: `go build ./...`
и `go test ./internal/httpapi/...` проходят, маршрут `POST /v1/chat/completions`
обслуживается через реальный mux, без ключа отвечает 401, а размеченные
значения в перехваченном теле не появляются. Сам `server.go` не изменялся.

### Что сделано

- `internal/llm/client.go` — OpenAI-совместимый клиент: переиспользуемый
  `http.Client` с пулом соединений и keep-alive, дедлайн на весь вызов из
  конфигурации, проброс и учёт отмены контекста. Повторы — только для сетевых

  задержкой, учётом `Retry-After` и остановкой по дедлайну; 400/401/403 не
  повторяются. Ключ уходит в `Authorization` **без** префикса `Bearer`.
  В тексты ошибок не попадают ни ключ, ни тело запроса, ни тело ответа модели.
- `internal/llm/stub.go` — детерминированный режим без сети; ответ цитирует
  полученные плейсхолдеры, разбор масок ручной, без `regexp`.
- `internal/gateway/proxy.go` — единственная точка выпуска наружу. Пять
  предусловий перечислены в коде и проверяются до вызова модели; `model.Chat`
  расположен строго ниже всех проверок. Предусловие «все спаны заменены»
  проверяется строже формального: защищённый текст не должен содержать ни
  одного исходного значения, иначе запрос отклоняется целиком. Ответ модели
  обрабатывается одним проходом: восстанавливаются только маски, выданные в
  этом же запросе и разрешённые политикой, а ПД, порождённые самой моделью,
  маскируются с продолжением нумерации запроса.
- `internal/httpapi/proxy.go` — `POST /v1/chat/completions`, ключ из
  `Authorization: Bearer <ключ>` или `X-API-Key`, сопоставление через
  `snap.Consumers.ByKey`; 401 без указания причины. Клиент модели собирается
  из снимка конфигурации и пересобирается при изменении настроек. Метрики:
  `obs.EndpointChat` / `obs.OpProxy`, время модели учитывается `Metrics.LLM`
  и вычитается из времени ответа сервиса.
- Тесты: `internal/llm/client_test.go`, `internal/gateway/proxy_test.go`,
  `internal/httpapi/proxy_test.go`. В сеть не ходят: downstream — httptest.
