## Цель

Построить независимый размеченный корпус для оценки качества детекции.

## Ключевое требование

Корпус **не должен** порождаться теми же грамматиками, которыми работает
детектор. Иначе оценка проверяет совпадение кода с самим собой, а не качество.
Генератор пишется как отдельный инструмент со своими шаблонами и своими
словарями значений; справочники из `internal/detect/dict` использовать нельзя.

## Что сделать

Отдельный Go-модуль в `tools/corpusgen/` со своим `go.mod`, независимый
от `ai-gateway`.

Элемент корпуса — естественный текстовый запрос к ассистенту, в который
встроены персональные данные, а не изолированная строка со значением.
Пример: «Найди клиента Иванова Ивана Ивановича, паспорт 4509 123456,
и покажи его адрес».

Формат вывода — JSON Lines, одна запись на строку:

```json
{"id":"c-0001","text":"...","spans":[{"start":14,"end":34,"type":"full_name"}],"traps":[{"start":..,"end":..,"type":"full_name","reason":"public_figure"}]}
```

Смещения — **байтовые**, согласованы с `text`.

Состав корпуса:

- все 17 обязательных типов ПД, каждый не менее чем в 60 записях;
- вариации написания по ТЗ §2.2: регистр, порядок компонентов даты, дата
  словами, разделяющие слова «серия … номер …»;
- ловушки: поэт Пушкин, улица Пушкина, адрес отделения банка, телефон
  горячей линии, номер договора. Для ловушек заполняется `traps`, а не `spans`;
- сложные предложения с несколькими типами ПД сразу;
- записи вовсе без ПД — для оценки ложных срабатываний;
- длинные тексты: несколько записей по 50 000 и 100 000 токенов.

Флаги: `-out`, `-count`, `-seed`, `-long`. Фиксированный seed даёт
воспроизводимый корпус — это обязательно, иначе метрики нельзя сравнивать
между прогонами.

Все данные синтетические. Реальные имена, адреса, телефоны и номера карт
в корпус не попадают; номера карт генерируются в тестовых диапазонах.

## Критерии приёмки

- [x] AC-1 Отдельный модуль, не импортирует `ai-gateway`.
- [x] AC-2 Все 17 типов представлены, каждый не менее чем в 60 записях.
- [x] AC-3 Ловушки всех пяти видов присутствуют и размечены в `traps`.
- [x] AC-4 Есть записи без ПД и длинные записи на 50 000 и 100 000 токенов.
- [x] AC-5 Один seed даёт побайтово одинаковый корпус.
- [x] AC-6 Смещения байтовые: фрагмент `text[start:end]` равен ожидаемому значению. Проверено тестом на кириллице.
- [x] AC-7 Вариации написания по ТЗ §2.2 присутствуют для дат и паспорта.
- [x] AC-8 `go test ./...` в модуле проходит, `go vet` чист, `gofmt -l` пуст.

## Команда проверки

```bash
cd tools/corpusgen
gofmt -l . && go vet ./... && go test ./...
```

## Журнал

- 2026-09-22 — задача создана оркестратором.
- 2026-09-22 — реализовано, `status: review`.

**Что сделано.** Отдельный Go-модуль `tools/corpusgen/` (`module corpusgen`,
go 1.26, только стандартная библиотека): `main.go` — CLI, `corpus/record.go` —
формат и строитель текста со смещениями, `corpus/vocab.go` — собственные
словари и склонение, `corpus/format.go` — форматтеры значений и вариаций,
`corpus/templates.go` — шаблоны запросов, `corpus/traps.go` — ловушки и
однофамильцы, `corpus/long.go` — длинные тексты, `corpus/generate.go` —
планировщик и сводка, `README.md` — формат и соглашения о границах спанов.

Смещения не вычисляются постфактум: текст собирается из кусков (`piece`), и
строитель запоминает границы значения по длине уже записанного буфера. Разойтись
с текстом они не могут по построению, но это всё равно проверяется тестом.

**Корпус по умолчанию** (`-count 1200`, seed 20260922): 1204 записи, 315 695
токенов, 4,9 МБ; single 708, multi 216, trap 144, clean 96, namesake 36, long 4.
Покрытие по типам от 69 (`pin`) до 254 (`full_name`) записей при минимуме 60.
Ловушки: public_figure 31, toponym 23, org_address 23, hotline 23,
contract_number 23, event_date 21.

**Проверка.** `gofmt -l .` — пусто, `go vet ./...` — код 0, `go test ./...` —
код 0 (11 тестов в `corpus`, прогнаны, вывод прочитан). Дополнительно
сгенерирован корпус и проверен вручную: все 4899 размеченных фрагментов
удовлетворяют `text[start:end] == value` при независимой сверке на Python;
два прогона с одним seed дали побайтово идентичные файлы (`cmp`), с разными —
разные. Просмотрены глазами 20 записей: текст — естественные запросы к
ассистенту, спаны указывают ровно на значение.

**Независимость от детектора.** `internal/detect/` и `internal/detect/dict/`
не открывались; словари, шаблоны, форматтеры и реализации Луна и контрольных
разрядов ИНН написаны для этого модуля заново. `TestNoGatewayImports` разбирает
импорты всех файлов модуля и падает на импорте `ai-gateway` или любой внешней
зависимости; `TestModuleIsStandalone` сторожит отсутствие `require` в `go.mod`.

  `AGENTS.md` §3 и `07-clarifications.md` §7.1, но с фактической разметкой

- Сам файл корпуса в репозиторий не кладётся: генерируется по требованию, чтобы
