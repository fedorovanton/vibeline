## Почему задача появилась

Тесты инвариантов T-19 нашли шесть дефектов в шлюзе и маскировании. Полное
описание, входы и причины — в журнале [T-19](T-19-invariant-tests.md),
раздел «Найденные дефекты».

| Дефект | Серьёзность | Суть |
|---|---|---|
| D-1 | высокая | `/v1/*`: нумерация плейсхолдеров сбрасывается в каждом сообщении, два разных человека уходят как `[ФИО_1]` и не восстанавливаются |
| D-2 | средняя | `/v1/*`, `synthetic`: синтетика в ответе модели маскируется повторно вместо восстановления |
| D-3 | низкая | `/v1/*`: буквальный `[ФИО_1]` во входе совпадает с выданным и при восстановлении заменяется значением |
| D-5 | низкая | `mask.Apply` паникует на спане `Start > End` |
| D-6 | низкая | `scopedKey` неинъективен при нулевом байте в `id` потребителя |
| D-8 | средняя | `verifyReplaced` (`VerifyReplaced`) ищет значение подстрокой: CVV `123` в «1230 рублей» даёт ложный fail-closed и HTTP 500 |

## Требования

- Инварианты AGENTS.md §3 и §7 сохраняются: fail-closed на `/v1/*`, запись в
  `Store` до ответа, чистая функция маскирования, нумерация по первому
  появлению. Ослаблять `VerifyReplaced` можно только до проверки по границам
  токена/значения — открытое значение по-прежнему обязано ловиться.
- Поведение `POST /process` на обычных входах **не меняется побайтово**
  (эталон `benchmarkGolden`, `internal/httpapi` и `internal/gateway`
  тесты `/process`). Если исправление D-3 меняет нумерацию на `/process` для
  входа с буквальным плейсхолдером — допустимо, это оговорить в журнале.
- `VerifyReplaced` используется и в `internal/httpapi/api.go` — сигнатуру не
  менять, либо поменять согласованно (api.go тогда добавить в owns и журнал).
- Снять `t.Skip` у тестов D-1, D-2, D-3, D-5, D-6, D-8.

  **D-1 (нумерация по сообщениям).** В `internal/mask/mask.go` нумерация
  вынесена в тип `Numbering`; `Applier.Apply` по-прежнему нумерует с нуля, а
  новый `ApplyNumbered` продолжает переданную нумерацию. `Proxy` держит одну
  `Numbering` на весь запрос и маскирует каждое сообщение через
  `Service.mask(…, num)` (`internal/gateway/gateway.go`); публичный
  `Service.Mask` не изменился. Одно значение во всех сообщениях — один номер,
  разные — разные. Тесты: `TestInvariantProxyNumberingAcrossMessages` (без
  Skip), `TestProxyNumberingSharedAcrossMessages`,
  `TestApplyNumberedContinuesAcrossTexts`.

  **D-8 (VerifyReplaced подстрокой).** `VerifyReplaced` ищет вхождения по
  границам цифрового токена: вхождение, продолженное ASCII-цифрой там, где
  значение начинается или заканчивается цифрой, — часть другого числа. Буква
  вплотную границей не считается сознательно: email, прилипший к букве,
  по-прежнему отклоняет запрос (лучше отказ, чем пропуск). Сигнатура не
  менялась, `internal/httpapi/api.go` не трогался. Тесты:
  `TestInvariantProxyShortValueInsideOtherNumber` (без Skip),
  `TestVerifyReplacedTokenBoundaries` (10 случаев: внутри числа — пропуск;
  отдельный повтор, повтор в начале/конце, через дефис, прилипший к букве,
  email с буквой — отказ), `TestProxyStandaloneShortValueStillFailsClosed`
  (открытый CVV отдельным токеном → `ErrFailClosed`, ноль запросов в модель).

  **D-2 (синтетика маскируется повторно).** `restoreAndRescan` переписан:
  сначала `scope.restore` подставляет исходные значения на место выданных
  масок (или оставляет маску как есть при `demask: false` и у неоднозначной
  маски) и запоминает эти участки; затем детекция идёт по восстановленному
  тексту, и найденное внутри этих участков не маскируется. Спан, частично
  заходящий на участок, маскируется остатком (дописанное моделью — новые
  данные). Дополнительно нумерация запроса к модели не выдаёт замену, уже
  выданную другому значению: synthetic при сдвиге (`repl == orig`) попадала на
  замену соседа, и два человека становились одной неоднозначной маской —
  найдено усиленным эхо-свойством. На `/process` правило не действует. Тесты:
  `TestInvariantProxySyntheticEchoRestores` (без Skip),
  `TestProxyDemaskDeniedKeepsSyntheticMasks`,
  `TestProxyMasksModelExtensionOfRestoredValue`,
  `TestNumberingAvoidsDuplicateReplacement`.

  **D-3 (буквальный плейсхолдер во входе).** Выбрано «нумерация не выдаёт
  плейсхолдер, уже буквально присутствующий во входе»: `Numbering.Reserved`
  на прокси проверяет замену по всем сообщениям запроса (с памятью), номер
  пропускается (не более 64 подряд). Для стратегий, где замена не зависит от
  номера (token, asterisks), пропуск невозможен — такая маска помечается в
  области неоднозначной и не восстанавливается ни на месте буквальной, ни на
  месте выданной. На `/process` не применяется: там обратный шаг возвращает
  сохранённый оригинал, и вывод `/process` не меняется ни на каком входе.
  Тесты: `TestInvariantProxyLiteralPlaceholderInInput` (без Skip),
  `TestNumberingSkipsReservedReplacement`, `TestNumberingReservedTerminates`,
  `TestProxyLiteralTokenInInputIsNotRestored`.

  **D-5 (паника на Start > End).** Условие пропуска в `Applier.apply`
  дополнено `s.End <= s.Start`: пропускаются перевёрнутый и пустой спаны
  (движок таких не выдаёт). Тесты: `TestInvariantApplyInvertedSpanDoesNotPanic`
  (без Skip), `TestApplySkipsEmptyAndInvertedSpan`.

  **D-6 (scopedKey неинъективен).** Ключ — `<длина id потребителя>:<id
  потребителя><payload_id>`; по длине ключ делится однозначно при любых
  байтах. Аллокаций на построение ключа по-прежнему одна (замер
  `testing.AllocsPerRun`). Тест: `TestInvariantScopedKeyIsInjective` (без Skip).

  **Усиление теста.** `TestInvariantProxyEchoRoundTripProperty` теперь
  проверяет placeholder, token и synthetic, генератор включает фрагменты,
  похожие на маску, а побайтовое равенство эха требуется для каждого
  принятого входа (раньше — только если повторная детекция на защищённом
  тексте ничего не находила). RESULT: placeholder — 391 вход побайтово,
  9 отказов защиты; token — 390/10; synthetic — 386/14 из 400. Отказы —

  «0041» только в одном месте), штатная работа `VerifyReplaced`.
