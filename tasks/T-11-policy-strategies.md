## Цель

Дополнить набор стратегий маскирования до четырёх и покрыть тестами политику
потребителя, правила по комбинациям типов и разбор конфигурации.
Это закрывает два пункта дополнительных возможностей ТЗ §6.

  стратегий (`mask.Register`, `mask.ByName`), стратегии `placeholder`

- `internal/policy/policy.go` — `Consumer`, `Combo`, `Filter`. **Не трогать.**

## Что сделать

### Стратегия `token` (`token.go`)

Обратимая непрозрачная замена: `{{pii:a3f1c2d4}}`. Токен детерминированно
выводится из типа и значения — одинаковые значения дают одинаковый токен,
разные значения не сталкиваются в пределах запроса.

Это отдельный пункт ТЗ §6 («токенизация/детокенизация»), и он же полезен, когда
потребитель не хочет раскрывать модели даже тип данных.

Требование: детерминированность. Два вызова с одним значением обязаны дать
одинаковый токен. Использовать `maphash` с фиксированным seed либо FNV —
криптостойкость здесь не нужна и не заявляется, о чём написать комментарием.

### Стратегия `synthetic` (`synthetic.go`)

Замена правдоподобными вымышленными данными: `Иванов Иван` → `Петров Пётр`,
`+7 916 123-45-67` → `+7 900 000-00-00`, `ivan@mail.ru` → `user1@example.org`.

Смысл запроса для модели сохраняется лучше, чем при любой другой стратегии —
это второй пункт ТЗ §6.

Правила по типам:

| Тип | Замена |
|---|---|
| `FullName`, `CardHolder` | из справочника `synthetic_names.txt` по номеру значения |
| `Phone` | `+7 900 000-00-NN` |
| `Email` | `userNN@example.org` |
| `CardNumber` | номер из тестового диапазона, проходящий Луна |
| `INN`, `SNILS` | синтетический номер с верной контрольной суммой |
| даты | `01.01.1970` со сдвигом по номеру |
| `Address`, `BirthPlace` | из небольшого встроенного списка вымышленных адресов |
| остальные | `[ТИП_N]`, как у `placeholder` |

Замены обязаны быть детерминированными по номеру значения и **не совпадать**
с реальными данными: домен `example.org` зарезервирован стандартом, диапазон
телефонов `+7 900 000-…` — заведомо служебный.

Справочник `synthetic_names.txt` встраивается через `//go:embed` внутри пакета
`mask` (не в `detect/dict`): это данные маскирования, а не детекции. Не менее
50 фамилий и 50 имён.

### Тесты политики (`internal/policy/policy_test.go`)

- Правило комбинации: ПИН без номера карты не маскируется, ПИН вместе с
  номером карты маскируется. То же для CVV.
- Несколько правил комбинаций применяются независимо.
- `MaskingEnabled: false` полностью отключает маскирование и это видно в
  результате `Filter`.
- Список типов потребителя ограничивает результат: тип вне списка не
  маскируется.
- `Strategy` возвращает стратегию из `per_type`, а при её отсутствии —
  стратегию по умолчанию.
- `NewConsumer` отклоняет неизвестное имя стратегии и пустые списки в правиле
  комбинации, с внятным сообщением.

### Тесты конфигурации (`internal/config/load_test.go`)

- Значения по умолчанию подставляются для пропущенных полей.
- `types: [all]` разворачивается в полный набор типов.
- Неизвестный тип ПД, неизвестный профиль, неизвестный режим модели и
  неизвестная стратегия дают ошибку с указанием потребителя и поля.
- Два потребителя с одинаковым идентификатором или одинаковым ключом —
  ошибка.
- Отсутствие потребителя `benchmark` — ошибка: без него `/process` не сможет
  выбрать политику.
- Длительности и размеры читаются в обеих формах: `30m` и число, `8MiB`
  и число байт.
- `Holder.Reload` с испорченным файлом **не заменяет** действующий снимок.
  Это ключевой тест: невалидное обновление не должно ронять работающий сервис.

### Тесты применения масок (`internal/mask/mask_test.go`)

- Одинаковые значения одного типа получают один номер и одну замену.
- Разные значения — разные номера.
- Текст вне спанов сохраняется побайтово, включая пунктуацию и пробелы.
- Кириллица: замена по байтовым смещениям не сдвигает соседний текст.
- Пустой список спанов возвращает исходный текст без изменений.

### Что сделано

**`internal/mask/token.go`** — стратегия `token`, формат `{{pii:a3f1c2d4}}`
(восемь шестнадцатеричных знаков, как задокументировано в README). Токен —
FNV-1a 64 бита от типа и значения, старшие 32 бита в hex. Номер значения `seq`
в токен намеренно не входит: одно значение даёт один токен и в разных запросах.
Криптостойкость не требуется и не заявляется — об этом написано комментарием,
там же честно отмечено, что токен не защищает от подбора по известному
значению и что при 32 битах возможна склейка двух значений в один токен.

**`internal/mask/synthetic.go`** — стратегия `synthetic` по таблице типов из
задачи. Все замены из заведомо служебных диапазонов: домен `example.org`
(RFC 2606), телефоны `+7 900 000-…`, ИНН с несуществующим кодом налогового
органа `0000`, карты из тестового диапазона `4000 00…`. Контрольные суммы
считаются в пакете `mask` (веса ИНН продублированы: в `detect` они
неэкспортируемые) и сверяются с `detect.Luhn`, `detect.INN`, `detect.SNILS`
в тестах. Детерминированность — только арифметика по `seq`, без `math/rand`
и без состояния между вызовами.

Два отступления от буквы задачи, оба осознанные:

1. *Телефон.* Варьируются четыре последние цифры, а не две. При двух цифрах
   101-е значение в запросе повторило бы первое, и два разных телефона
   склеились бы в один. Для первых ста значений форма ровно как в задаче
   и README: `+7 900 000-00-NN` (тест `TestSyntheticPhoneDocumentedForm`).
2. *Место рождения.* Для `BirthPlace` берётся населённый пункт (часть адреса
   до первой запятой), а не полный адрес с улицей и квартирой: «Место
   рождения: г. Тестоград, ул. Примерная, д. 1, кв. 1» читается моделью как
   испорченные данные. Список адресов при этом один, как и требовалось.

Отдельно: обнаружено и закрыто нарушение REQ-301 — при конечном справочнике
замена рано или поздно совпадает с самим исходным значением (настоящий
«Петров Пётр» на первом номере получал бы «Петров Пётр», то есть значение
осталось бы открытым). Добавлен сдвиг на одну позицию при совпадении; размен
(сдвинутая замена может совпасть с заменой соседнего значения) описан
комментарием и покрыт `TestSyntheticNeverReturnsOriginal`.

**`internal/mask/data/synthetic_names.txt`** — 60 фамилий, 52 имени,
40 отчеств, `//go:embed` внутри пакета `mask`. Все записи в мужской форме:

несогласованные тройки вида «Петров Анна Петрович».

### Блокер: `internal/config/types.go`, `Duration.UnmarshalYAML`

Длительность **не читается числом секунд**, хотя эта форма заявлена
комментарием к методу, текстом его собственной ошибки («длительность должна
быть строкой вида "30m" или числом секунд») и списком проверок T-11.

Причина (проверена отдельным прогоном, не гипотеза): `yaml.v3` успешно
разбирает нетипизированный скаляр `1800` в `string`, поэтому первая же ветка
`unmarshal(&s)` забирает значение себе и падает на `time.ParseDuration`,
не дойдя до числовой ветки. `store.ttl: 1800` роняет загрузку конфигурации
целиком.

Файл вне `owns` задачи T-11, поэтому не тронут. Исправление — привести порядок
веток к тому же, что в рядом лежащем `Bytes.UnmarshalYAML` (сначала число,
затем строка); в таком порядке разбираются обе формы, это проверено
экспериментально. После правки `TestDurationsAsSeconds` в
`internal/config/load_test.go` должен позеленеть без изменений самого теста.
