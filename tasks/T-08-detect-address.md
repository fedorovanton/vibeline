## Цель

Находить адреса и их отдельные компоненты: страну, индекс, регион, город,
улицу, дом, корпус, строение, квартиру. ТЗ считает адрес одним типом с
обязательной поддержкой компонентов. Читать `tasks/CONTRACTS.md` перед началом.

## Что сделать

Сканер `address`, регистрируется через `detect.Register` в `init`.
Тип результата — `pii.Address`.

### Стратегия

Улицы списком не ведутся: их сотни тысяч. Адрес собирается вокруг
**маркеров компонентов**, а город и регион подтверждаются справочником.

Признаки, по которым начинается сборка адреса:

1. Маркер компонента: `г.`, `гор.`, `город`, `ул.`, `улица`, `пр-т`,
   `проспект`, `пр-д`, `проезд`, `пер.`, `переулок`, `б-р`, `бульвар`,
   `ш.`, `шоссе`, `наб.`, `набережная`, `пл.`, `площадь`, `мкр.`,
   `микрорайон`, `д.`, `дом`, `корп.`, `корпус`, `стр.`, `строение`,
   `влд.`, `владение`, `кв.`, `квартира`, `оф.`, `офис`, `обл.`,
   `область`, `р-н`, `район`, `край`, `респ.`, `республика`.
2. Почтовый индекс: ровно 6 цифр, первая не ноль.
3. Город или регион из справочника с заглавной буквы.

### Сборка спана

Адрес — **один спан** типа `pii.Address`, покрывающий непрерывную цепочку
компонентов. Цепочка растёт вправо и влево, пока соседние токены являются
компонентами адреса: маркер, число, топоним из справочника, капитализированное
слово сразу после маркера улицы.

Границы спана: сокращения-маркеры **включаются** в спан, когда они внутри
цепочки (`Москва, ул. Ленина, д. 5, кв. 12` — один спан целиком), поскольку
без них адрес не читается как адрес и обрывать цепочку по каждому «д.»
означало бы породить множество огрызков. Но текст до начала адреса
(«проживает по адресу») в спан **не входит**.

Обоснование этого выбора зафиксировать комментарием в коде.

### Уверенность

| Условие | Уровень |
|---|---|
| Индекс плюс город из справочника плюс улица с номером дома | `Certain` |
| Не менее двух компонентов с маркерами (`ул.` и `д.`, `г.` и `ул.`) | `Strong` |
| Один компонент с маркером либо одинокий город из справочника | `Weak` |

### Справочники

- `geo_cities.txt` — города России, не менее 1000 записей. Метка: тип
  населённого пункта (`city`, `town`, `village`). Обязательно включить все
  областные центры и города-миллионники.
- `geo_regions.txt` — 85 субъектов РФ и их распространённые сокращения.
  Метка не используется.
- `address_markers.txt` — маркеры компонентов. Метка: имя компонента
  (`city`, `street`, `house`, `flat`, `region`, `index`, `building`).
  Справочник, а не константы в коде: ТЗ требует расширяемости без правки ядра.

### Чего делать НЕ надо

Контр-правила — задача T-10. Адрес отделения банка регистрируй как кандидата,
вето поставит другой сканер. Не пытайся исключать «отделение банка» здесь.

## Критерии приёмки

- [x] AC-1 `г. Москва, ул. Ленина, д. 5, кв. 12` — один спан, покрывает всю цепочку.
- [x] AC-2 `101000, Москва, Тверская 5` — один спан, `Certain` (есть индекс).
- [x] AC-3 `проживает по адресу Санкт-Петербург, Невский проспект, 28` — спан начинается с «Санкт-Петербург», слова «проживает по адресу» вне спана.
- [x] AC-4 Компоненты по отдельности: `Московская область`, `индекс 143000`, `кв. 45` — находятся хотя бы как `Weak`.
- [x] AC-5 Регистр не влияет: `Г. МОСКВА, УЛ. ЛЕНИНА, Д. 5` находится.
- [x] AC-6 Одиночное число `5` в тексте без маркеров адресом не считается.
- [x] AC-7 Смещения байтовые: спан, вырезанный из `doc.Text` по `Start:End`, равен ожидаемой строке на кириллице.
- [x] AC-8 `geo_cities.txt` содержит не менее 1000 городов, `geo_regions.txt` — 85 субъектов.
- [x] AC-9 Таблично-ориентированные тесты, только синтетические данные.
- [x] AC-10 `go test ./internal/detect/...` проходит, `go vet` чист, `gofmt -l` пуст.
- [x] AC-11 Бенчмарк `BenchmarkScanAddress` на тексте ~4 КБ: 0 allocs/op.

  «Ленобласть» + страна «Россия»/«РФ» как компонент адреса),
  `address_markers.txt` — 74 маркера с метками
  `city|street|house|flat|region|index|building`.

  **Как собирается адрес.** Цепочка компонентов растёт слева направо и
  закрывается на первом постороннем токене; разделителями внутри цепочки
  допускаются `, . - /` (не более двух подряд) и пробелы (не более трёх);
  перевод строки цепочку рвёт. Составные топонимы («Нижний Новгород»,
  «Ростов-на-Дону», «Ханты-Мансийский автономный округ») ищутся срезом
  `doc.Norm` по последовательности до семи токенов — срез строки не аллоцирует.
  Название улицы без маркера принимается только внутри уже открытой цепочки:
  либо слева маркер, либо справа номер дома или маркер проезда («Тверская 5»,
  «Невский проспект»). Одиночное число цепочку не открывает никогда.

  **Уверенность.** `Certain` — индекс + город из справочника + улица с номером
  дома; `Strong` — два и более самостоятельных компонента; `Weak` — один
  компонент. Счёт ведётся по компонентам, а не по признакам: «г. Москва» — один
  компонент (маркер плюс его значение), поэтому остаётся `Weak`, как и требует
  таблица задачи.

  **Решение по границам спана (зафиксировано комментарием в коде).**
  Сокращения-маркеры включаются в спан, когда стоят ВНУТРИ цепочки:
  `Москва, ул. Ленина, д. 5, кв. 12` — один спан целиком; обрывать цепочку на
  каждом «д.» значило бы породить огрызки, которые не читаются как адрес и
  разваливают восстановленный текст. Но маркер, открывающий или закрывающий
  цепочку, в спан НЕ входит: `г. Москва, ул. Ленина` → спан начинается с
  «Москва»; `кв. 45` → спан «45». Это требование CONTRACTS.md (таблица границ:
  «ул. Ленина, д. 5» → правильный спан «Ленина, д. 5») и AGENTS.md (служебное
  слово на границе значения штрафуется как избыточность). Поэтому AC-1 закрыт
  спаном `Москва, ул. Ленина, д. 5, кв. 12` — вся цепочка компонентов без
  открывающего «г.». Если оркестратор читает AC-1 буквально («покрывает всю
  цепочку» вместе с «г.»), это правка одной строки в `flush`, но она разойдётся
  с контрактом.

  - Справочник городов в именительном падеже: «Приехал из Санкт-Петербурга» не

    ТЗ прямо называет индекс признаком начала адреса, а пропуск дороже маски.
