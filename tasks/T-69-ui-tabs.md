## Цель

Стенд вырос слоями: ввод, «что ушло в модель», тайминги, метрики, история,
трассировка и журнал шли одной лентой. Жюри приходилось листать, а
наблюдаемость терялась под результатом прогона. Задача — разнести страницу
по вкладкам и сделать настоящий дашборд с графиками по `/metrics`, не нарушая
ограничений стенда: один `web/index.html`, без сборки, без внешних ресурсов,
CSP `default-src 'none'`.

## Решения заказчика

- Вкладки: **Проверка жюри** (стартовая) · **Дашборд** · **История и
  трассировка** · **Журнал** · **Конфигурация**.
- Конфигурация — только просмотр. Политики потребителей без ключа не
  раскрываются (решение `handleConsumers`): на вкладке — то, что пришло с
  прогонов под ключом.

## Что сделать

- Каркас вкладок на `location.hash`: новых маршрутов нет, `handlePage` по-прежнему
  отдаёт только `/`. Ключ доступа — в шапке, общий для всех вкладок, с
  индикатором «принят / отклонён / не указан».
- Дашборд: полоса состояния (`/healthz`, `/readyz`), KPI со спарклайнами,
  фильтр эндпоинта, графики RPS/ошибок, Latency (средняя и p95 за интервал),
  TPS за 5 минут, ПД по типам, исходы, распределение времени ответа, запросы по
  эндпоинтам, хранилище и рантайм Go. Графики — свой inline SVG и div-бары.
- Журнал: поиск, счётчики уровней, кликабельный `request_id` → трассировка;
  бейдж новых warn/error на вкладке.
- Конфигурация: сервис, потребители, каталог типов ПД.
- `/api/v1/ui/consumers` отдаёт реестр типов ПД (`pii_types`): метрики несут
  машинные ключи, а второй словарь в JS разошёлся бы с `internal/pii`.

## Журнал

**2026-09-23, оркестратор.**

### Что сделано

- `web/index.html` разнесён на пять вкладок: «Проверка жюри» (стартовая),
  «Дашборд», «История и трассировка», «Журнал», «Конфигурация». Вкладка живёт
  в `location.hash`: прямые ссылки `/#dashboard` и т. п., кнопка «Назад»,
  стрелки/Home/End по вкладкам (WAI-ARIA `tablist`). Ни одно имя вкладки не
  совпадает с `id` на странице — иначе браузер прокручивал бы к элементу;
  тело таблицы истории переименовано `history` → `historyRows`.
- Ключ доступа переехал в шапку и общий для всех вкладок; индикатор «принят /
  отклонён / не указан» по ответам сервиса. Смена ключа забывает историю,
  журнал и трассировку прежнего владельца; ответ на прежний ключ, пришедший
  после смены, отбрасывается.
- Дашборд по открытым `/metrics`, `/healthz`, `/readyz` — работает без ключа:
  полоса состояния, 6 KPI со спарклайнами, фильтр эндпоинта, графики RPS и
  ошибок, Latency (средняя и p95 за интервал), TPS за 5 минут с перекрестием и
  подсказкой, ПД по типам (замаскировано / не маскируется политикой), исходы с
  долей успешных, распределение времени ответа по корзинам гистограммы,
  запросы по эндпоинтам с разбивкой по операциям, хранилище и рантайм Go.
  Ряды не хранятся, а выводятся из кольцевого буфера снимков `/metrics`
  (151 шт.) — смена фильтра пересчитывает графики мгновенно; сброс счётчиков
  при рестарте сервиса начинает ряды заново.
- Графики — свой inline SVG и div-бары: CSP `default-src 'none'` запрещает
  библиотеки. Пространство имён SVG берётся у значка в шапке, а не строкой —
  адрес пространства имён не прошёл бы `TestUIPageIsSelfContained`. Палитра
  рядов проверена `validate_palette.js --mode dark --surface #111a24`
  (скилл dataviz): все проверки PASS.
- Журнал: поиск, счётчики уровней с фильтром по щелчку, `request_id`
  записи потребителя ведёт в трассировку; бейдж новых warn/error на вкладке
  (накопленное до открытия страницы не считается).
- Конфигурация: сервис, потребители (политика — после прогона под ключом),
  каталог 23 типов ПД с отметкой обязательных по ТЗ, 8 сканеров.
- `GET /api/v1/ui/consumers` отдаёт `pii_types` из `pii.All()`: имена типов для
  дашборда без второго словаря в JS. Политики потребителей по-прежнему только
  через `/api/v1/analyze` под ключом.
- README: вкладки в «Инструкции для жюри», `pii_types` в таблице эндпоинтов.
