## Цель

ТЗ требует пять обязательных артефактов: рабочий сервис с README, инструкцию
для жюри, схему архитектуры и настроек, сведения о производительности и
дополнительных возможностях, ограничения и план развития. Всё это уже есть по
отдельности в README и `docs/spec/`, но жюри нужна одна точка входа, которую
можно листать на защите. Задача — собрать работу в HTML-презентацию со
слайдами, отдавать её самим сервисом по `GET /presentation` и развернуть план
развития до трёх горизонтов.

## Решения заказчика

- Презентация — файл в репозитории **и** страница сервиса `GET /presentation`.
- План развития — три горизонта: пилот, промышленная эксплуатация, платформа.
- После проверок выкатить `main` на публичный адрес (отдельное подтверждение).

## Что сделать

- `web/presentation.html`: один файл, встроенные CSS, JS и SVG, без внешних
  ссылок (тот же CSP, что у стенда). Листание колесом, клавишами и свайпом,
  `#N` на слайд, прогресс, обзор слайдов, печать по слайду на страницу.
- `web/web.go`: встроить файл; `internal/httpapi/ui.go`: маршрут
  `GET /presentation` с заголовками стенда.
- Ссылка «Презентация» в шапке стенда.
- README: ссылка на презентацию, седьмой дополнительный тип `bank_account`,
  план развития по горизонтам.

## Критерии приёмки

- [x] AC-1 `go vet ./...`, `go test ./...`, `go test -race ./internal/httpapi/...` проходят
- [x] AC-2 `GET /presentation` — 200, `text/html`, CSP как у стенда; в файле нет внешних ссылок и `console.log`
- [x] AC-3 все пять обязательных артефактов ТЗ отражены слайдами со ссылками на подтверждение

- [x] AC-5 `scripts/package.sh` собирает архив, `web/presentation.html` в нём
