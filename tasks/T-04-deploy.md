## Почему это самая дорогая задача проекта

Развёрнутый сервис с доступным `POST /process` — **единственный отсекающий
барьер**. Без него решение не оценивается вовсе: ни качество детекции, ни
производительность, ни документация роли не играют. Все остальные задачи
проекта вместе стоят меньше, чем эта одна.

Задача заведена отдельным файлом после аудита требований: она числилась на
доске, но не имела ни описания, ни критериев приёмки — то есть у самого
дорогого пункта не было владельца и определения готовности.

## Что уже готово

- `Dockerfile` — многостадийная сборка, статический бинарник, образ без
  оболочки и пакетного менеджера, непривилегированный пользователь.
- `docker-compose.yml` — проброс порта, монтирование конфигурации и `.env`,
  проверка живости силами самого бинарника, предел памяти, ротация журналов.
- `deploy/README.md` — запуск, проверка снаружи, перезагрузка настроек
  сигналом, наблюдение.
- `scripts/package.sh` — сборка архива с проверкой на секреты, запрещённые
  каталоги и крупные файлы.
- `scripts/demo.sh` — сценарии проверки для жюри с побайтовой сверкой
  восстановления.

## Что осталось

1. Получить доступ к серверу с публичным адресом.
2. Доставить проект, собрать образ, поднять сервис.
3. Задать переменные окружения: `ALFAGEN_API_KEY` обязательно, ключи
   потребителей по необходимости.
4. Проверить снаружи, а не с самого сервера.
5. Зафиксировать адрес в README и передать организаторам.

## Чем ограничен выбор площадки

Это не вопрос вкуса: два свойства решения отсекают часть вариантов.

1. **Соответствие «маска → оригинал» живёт в памяти процесса.** Так решено
   осознанно (DECISIONS.md §4): внешнее хранилище добавляет латентность и
   точку отказа, а производственная готовность не оценивается. Следствие
   жёсткое: между прямым и обратным шагом экземпляр обязан быть **тем же
   самым**. Любая площадка, где экземпляров несколько или они перезапускаются
   между запросами, ломает демаскирование — а критерий 2 обнуляется без
   возможности компенсации другими критериями.
2. **Память.** `store.max_bytes` — 1 ГиБ, предел контейнера `MEMORY_LIMIT` —
   4 ГБ по умолчанию и должен превышать хранилище с запасом. Машина меньше
   чем на 2 ГБ не годится, разумный минимум — 4 ГБ и 2 vCPU.

| Вариант | Годится для AC-6 | Что ломается |
|---|---|---|
| **VPS, один экземпляр** | да | ничего; нужна оплата и 20–40 минут |
| Туннель с ноутбука (Cloudflare Tunnel, ngrok) | нет — туннель искажает латентность и пропускную способность | замер снаружи перестаёт быть замером сервиса; ноутбук должен быть включён всё время проверки |
| Бессерверный контейнер, автомасштабирование | нет | холодный старт и смена экземпляра ломают **демаскирование**, то есть критерий 2 |

Вывод: **один VPS**. Туннель допустим только как запасной вариант на время
показа, и тогда числа в `PERFORMANCE.md` остаются замерами закрытого контура —
с явной оговоркой, а не молча.

Отдельно проверить с самой машины, что `alfagen.alfabank.ru` доступен: контракт
`POST /process` модель не вызывает, но демонстрационный стенд и прокси —
вызывают, и без доступа режим `llm.mode: alfagen` придётся переключать на
`stub` прямо на показе.

## Критерии приёмки

- [x] AC-1 `POST /process` отвечает по публичному адресу с внешней машины.
- [x] AC-2 Прямой шаг возвращает маску, обратный — исходную строку побайтово.
- [x] AC-3 `GET /healthz` и `GET /readyz` отвечают; `/readyz` показывает
      действующих потребителей и подключённые сканеры.
- [x] AC-4 `GET /metrics` отдаёт метрики в формате Prometheus.
- [x] AC-5 Сервис переживает перезапуск контейнера и поднимается сам.
- [x] AC-6 Нагрузочный прогон выполнен **против публичного адреса**, а не
      локально: до сих пор все замеры делались на loopback.
- [x] AC-7 Ключей и персональных данных нет ни в журнале контейнера, ни в
      переменных, видимых снаружи.
- [ ] AC-8 Адрес записан в README и передан организаторам.

## Команда проверки

```bash
HOST=http://<публичный-адрес>:8080
curl -sS $HOST/healthz
curl -sS -X POST $HOST/process -H 'Content-Type: application/json' \
  -d '{"payload":"Клиент Иванов Иван Иванович, паспорт 4509 123456","payload_id":"deploy-1"}'
bash scripts/demo.sh $HOST
```
