## Цель

Инструмент измерения печатал нули с пометкой `RESULT` и завершался с кодом 0,
когда не прошёл ни один запрос.

## Как это выяснилось

Нашла сессия «Замечания жюри техэксперта» 22.09.2026: команда из README била
в корень вместо `/process`, сервис отвечал 405 на каждый запрос, инструмент
напечатал «goodput 0 запр/с (RESULT)», «Измеренное среднее: 0,000 мс (RESULT)»
и завершился успешно. Воспроизведено здесь: 29 612 ответов 4xx/5xx, код
возврата 0, пять строк с пометкой RESULT.

Опасность не в нулях, а в пометке рядом с ними. Латентность набирается только
по успешным ответам, поэтому чем больше отказов, тем ближе среднее к нулю —
то есть тем лучше выглядит провалившийся прогон. В отчёт о производительности
величины переносятся именно по пометке `RESULT`.

## Что сделано

1. `report.checkValidity` считает долю успешных ответов. Ниже 99 % прогон
   размечается недостоверным с указанием причины. Ответы 429 отказом не
   считаются: это штатное поведение сервиса под нагрузкой, для них отдельная
   колонка.
2. Пометка величин вычисляется: `RESULT` у достоверного прогона,
   `НЕДОСТОВЕРНО` у остальных. Числа остаются в выводе — по ним видно, что
   пошло не так.
3. Под шапкой отчёта печатается предупреждение с причиной и с подсказкой про
   `-url .../process`.
4. `run` возвращает ошибку при недостоверном прогоне — код возврата 1.
5. В Makefile цели `quality`, `load`, `load-long`, `load-limit` получили
   `set -o pipefail`. Без него пайп в `tee` возвращал код `tee`, и отказ
   инструмента терялся ровно там, где его никто не читает глазами.

## Критерии приёмки

- [x] AC-1 прогон по неверному адресу возвращает код 1
- [x] AC-2 в отчёте недостоверного прогона нет ни одной пометки RESULT
- [x] AC-3 здоровый прогон по `/process` не изменился: код 0, пометки RESULT на месте
- [x] AC-4 отказы по перегрузке (429) достоверности не отменяют — закреплено тестом
- [x] AC-5 код возврата доходит через пайп в `tee`

## Журнал

**2026-09-22, оркестратор.** Воспроизведено: `-url http://localhost:8080/`
вместо `/process` — 29 612 ответов с ошибкой, код 0, пять пометок RESULT.
После правки: код 1, ноль пометок RESULT, пять пометок НЕДОСТОВЕРНО,
предупреждение в шапке. Здоровый прогон по `/process`: код 0, goodput
2 240 запр/с, среднее 1,665 мс, шесть пометок RESULT.

Отдельно проверено, что `set -o pipefail` доносит код через `tee`: без него
тот же прогон через пайп даёт код 0, с ним 1. Без этой части правка
инструмента осталась бы бесполезной — цели Makefile пишут отчёт через `tee`.

Числа в `docs/spec/PERFORMANCE.md` снимались прогонами по `/process` и
провалом не затронуты — проверять их заново не требуется.
