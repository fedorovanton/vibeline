# Доска задач ai-gateway

Протокол работы — в [AGENTS.md](../AGENTS.md). Контракты пакетов — в [CONTRACTS.md](CONTRACTS.md).
Принятые решения — в [DECISIONS.md](../docs/spec/DECISIONS.md).

Таблица собирается из YAML-шапок самих задач и потому не может с ними разойтись.
Статусы: `backlog` → `in-progress` → `review` → `done`. Агент ставит `review`;
в `done` задачу переводит оркестратор после проверки интеграции на живом сервисе.

## Как брать номер

Над проектом работают несколько сессий сразу, каждая в своём рабочем дереве.
Номер, взятый как «следующий после последнего в моей ветке», уже сталкивался:
22.09.2026 две сессии независимо завели T-26, T-27, T-28 и T-29 — все четыре
номера разошлись по разным задачам одновременно.

Поэтому номера разведены по диапазонам, а не берутся подряд:

| Диапазон | Кто занимает |
|---|---|
| T-00 … T-25 | общая нумерация, занята полностью |
| T-26 … T-39 | сессии по замечаниям жюри: детекция, корпус, документы |
| T-40 … T-69 | основная сессия оркестратора: стенд, наблюдаемость, движок, замечания жюри 23.09 |
| T-70 … T-79 | параллельные сессии 23.09: сборка, поставка, мелкие правки |
| T-80 … T-89 | основная сессия оркестратора: замечания жюри раунда 5 |
| T-90 … T-99 | сессия качества кода 23.09: замечания автопроверки (SonarQube) |

Занятый номер проверяется по этому файлу **в `main`**, а не в своей ветке.
