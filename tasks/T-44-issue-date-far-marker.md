## Почему задача появилась

При проверке T-29 на живом сервисе:

```
паспорт выдан ГУ МВД России по Свердловской области двадцать пятого декабря
две тысячи седьмого, код подразделения 770-053
  →  паспорт выдан [ОРГАН_ВЫДАЧИ_1] [ДАТА_РОЖДЕНИЯ_1], код подразделения [КОД_ПОДРАЗДЕЛЕНИЯ_1]
```

Значение скрыто, но подпись неверна: на демонстрации дата выдачи с плашкой
«дата рождения» читается как ошибка отнесения (критерий 3). Причина —
`dateMarkerBefore` смотрит на четыре значимых слова слева, а название органа
выдачи длиннее, и маркер «выдан» в окно не попадает. Дата без маркера
получала тип `birth_date` с уверенностью `Weak` и держалась только на
подъёме по кластеру — под профилем без подъёма она не маскировалась бы вовсе.

## Что сделано

`dateIssueMarkerFar` — дальний поиск только маркера выдачи, до 12 значимых
слов, если ближнее окно маркера не дало. Поиск обрывается на числе (тогда
«выдан» относится к нему) и на маркере рождения или стоп-слове.

## Критерии приёмки

- [x] AC-1 «выдан ГУ МВД России по Свердловской области 25.12.2007» — дата
      выдачи, `Strong`; то же для даты словами.
- [x] AC-2 Число или маркер рождения между «выдан» и датой обрывают поиск —
      `TestDatesIssueMarkerFarStops`.
- [x] AC-3 Прогон качества не хуже прежнего; `BenchmarkScanDates` — 0 allocs/op.
