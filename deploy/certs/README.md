# Корневые сертификаты для вызова модели

`russian-trusted-ca.pem` — «Russian Trusted Root CA» и «Russian Trusted Sub CA»
Министерства цифрового развития. Ими подписан `alfagen.alfabank.ru`.

Зачем файл лежит в репозитории. Рабочий образ собран на
`gcr.io/distroless/static-debian12`, который несёт стандартный набор корневых
сертификатов. Этих двух в наборе нет, и обращение к модели из контейнера
отказывает на проверке сертификата, тогда как с машины разработчика тот же
вызов проходит: там сертификат стоит в системной связке по инструкции
организаторов (`docs/context/06-environment.md`, §6.1). Расхождение
обнаруживается только в контейнере, поэтому сертификаты встраиваются в образ,
а не устанавливаются на хосте развёртывания.

Секретом содержимое не является: это открытые корневые сертификаты, публично
распространяемые Минцифры. Приватных ключей здесь нет.

Срок действия: Sub CA — до 19.07.2029, Root CA — до 27.02.2032.

Проверить, что сертификатов достаточно:

```
curl -s -o /dev/null -w '%{http_code}\n' --cacert deploy/certs/russian-trusted-ca.pem \
  https://alfagen.alfabank.ru/continue-dev/v1/models
```

Ответ `401` означает успех: соединение по TLS установлено, а отказ пришёл уже
от приложения из-за отсутствия ключа доступа. Ошибка проверки сертификата
выглядит иначе — соединение не устанавливается вовсе.
